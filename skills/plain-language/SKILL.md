# Plain Language

Guidance for writing user-facing text — issue descriptions, MR bodies, docs, comments — so it reads as human-written. This is a passive reference: follow the checklist while you compose. It takes no input and does not rewrite existing text.

Apply judgement. These are defaults for prose and Markdown, not absolute bans. A word or an em-dash used because it is the right one is fine; the target is the reflexive overuse that marks machine text.

## Word choice

Avoid filler and inflated vocabulary: delve, tapestry, testament, underscore, showcase, pivotal, crucial, intricate, robust, landscape, meticulous, boasts, nestled, "in the heart of", "align with".

Prefer plain verbs. Write "is" and "are" instead of "serves as" or "stands as". Name the specific thing instead of praising it in the abstract.

## Rhetorical patterns

Avoid:

- Negative parallelism — "not just X, but Y".
- Rule-of-three triads used for rhythm rather than because there are three things.
- Undue-significance framing — "plays a crucial role", "highlights the importance of".
- Superficial "-ing" tails — "…, reflecting a broader trend".
- Vague attribution — "observers note", "experts argue".
- Promotional or press-release tone.
- Canned wrap-up sections like "Challenges and Future Prospects".

## Formatting

Avoid:

- Bold on every key term.
- List items shaped as **Bold header:** followed by a colon and explanation, when a plain sentence works.
- Em-dash overuse.
- Title Case Headings — use sentence case.
- Emoji as bullets.
- Curly quotes and apostrophes — use straight ones.
- Wrapping a short answer in headers and bullets it does not need.

## Prefer instead

- Concrete specifics over generic praise.
- Varied, natural sentence length.
- Only as much structure as the content needs. A two-sentence answer is two sentences.
